Відео й аудіо на вебсторінці

Сьогодні ми навчимо HTML показувати відео та відтворювати звук. Працюємо в парах. Наприкінці кожна пара створить правильний фрагмент коду й перевірить себе.

Аналогія Теги Практика Перевірка Педагогу

1. Уявіть медіаплеєр як рамку

<video> або <audio> — це рамка-плеєр.

src — адреса файлу, ніби напис на коробці: «бери запис звідси».

controls — кнопки плеєра: старт, пауза, гучність.

<source> — запасні ключі. Браузер пробує джерела по черзі й бере формат, який розуміє.

Головна думка: HTML не створює відео чи звук. Він підказує браузеру, де лежить файл і як його показати.

2. Теги й атрибути

Відео

<video controls width="640" poster="images/cover.jpg">
  <source src="media/lesson.mp4"
          type="video/mp4">
  Ваш браузер не підтримує відео.
</video>
  • controls додає кнопки керування.
  • width задає ширину в пікселях.
  • poster показує обкладинку до запуску.

Аудіо

<audio controls>
  <source src="media/podcast.mp3"
          type="audio/mpeg">
  Ваш браузер не підтримує аудіо.
</audio>
  • <audio> не має зображення.
  • controls потрібен, щоб учень міг запустити запис.
  • Текст усередині — запасне повідомлення.

Корисні атрибути

controls
Показує панель керування. Значення не потрібне.
autoplay
Пробує запустити медіа одразу. Браузер часто блокує звук.
muted
Вимикає звук. Часто потрібен разом з autoplay.
loop
Повторює запис після завершення.
preload
Підказує, що завантажувати наперед: none, metadata або auto.
type
Описує формат файлу. Наприклад, video/mp4.

Важливо: не вмикайте звук автоматично. Це заважає користувачам. Для навчальної сторінки краще дати кнопку запуску через controls.

3. Практична робота в парах

Роль 1

Верстальник

Набирає код у VS Code. Стежить за тегами, лапками й шляхами.

Роль 2

Тестувальник

Відкриває HTML у Chrome. Перевіряє кнопки, звук, відео та повідомляє про помилки.

Через 12 хвилин поміняйтеся ролями. Якщо за комп’ютером троє, третя роль — «консультант»: читає завдання та звіряє код зі зразком.

  1. Створіть папки. Поруч із вашим HTML-файлом зробіть папку media. Покладіть туди надані педагогом файли lesson.mp4 і podcast.mp3.
  2. Додайте відео. Використайте приклад вище. Не змінюйте меню, CSS або інші частини свого проєкту.
  3. Додайте аудіо. Розмістіть його після відео. Додайте запасне повідомлення для браузера.
  4. Перевірте в Chrome. Чи є кнопки? Чи запускаються обидва файли? Чи працює пауза?
  5. Перевірте HTML. Усі відкриті теги мають бути закриті. Шляхи й назви файлів мають збігатися точно.

Якщо медіафайлів немає: педагог має заздалегідь надати локальні файли. Без них можна перевірити код і вигляд плеєра, але не саме відтворення.

4. Інтерактивна перевірка

Виконайте 6 завдань. Правильні відповіді наперед не показані.

1. Який тег вставляє відеоплеєр?
2. Який атрибут показує кнопки старту, паузи й гучності?
3. Оберіть правильний тип для MP3-файлу.
4. Відновіть рядок із джерелом відео.
5. Що найімовірніше сталося, якщо плеєр є, але файл не запускається?
6. Який варіант найкращий для навчальної сторінки?
Оберіть відповіді й натисніть «Перевірити».

5. Типові помилки

Плеєр є, файл не грає

Причина: неправильний шлях або регістр літер.

Виправлення: звірте media/lesson.mp4 з реальною папкою та назвою.

Немає кнопок

Причина: пропущено controls.

Виправлення: додайте атрибут у відкривальний тег.

Код після плеєра «ламається»

Причина: немає </video> або </audio>.

Виправлення: закрийте тег і перевірте вкладеність.

Файл працює лише на одному ПК

Причина: абсолютний шлях на кшталт C:\Videos\....

Виправлення: використайте відносний шлях media/....

6. Організація заняття для педагога

План на 90 хвилин

  • 0–10 хв: мета й аналогія.
  • 10–30 хв: показ тегів та атрибутів.
  • 30–35 хв: розподіл ролей.
  • 35–65 хв: практична робота, зміна ролей після 12 хв.
  • 65–78 хв: інтерактивна перевірка.
  • 78–88 хв: виправлення типових помилок.
  • 88–90 хв: короткий підсумок.

Підготовка

  • Відкрити цей файл у Chrome.
  • Підготувати VS Code.
  • За можливості дати локальні файли MP4 і MP3 з безпечним навчальним змістом.
  • Не покладатися на інтернет.
  • Не просити учнів змінювати CSS, меню чи структуру їхнього проєкту.

Очікуваний результат: учень пояснює призначення <video>, <audio>, <source>, src, type і controls; додає локальні MP4 та MP3; знаходить помилку у шляху; перевіряє роботу сторінки в Chrome.

Ключ для педагога — відкрити після виконання
  1. <video>.
  2. controls.
  3. audio/mpeg.
  4. <source>, шлях media/lesson.mp4, тип video/mp4.
  5. Помилка у шляху або назві файлу.
  6. Є controls, користувач запускає запис сам.

Критерій успіху: 5–6 балів — тему засвоєно; 3–4 — виправити помилки за підказками; 0–2 — ще раз пройти приклади разом із партнером.

Що перевірити додатково: реальне відтворення залежить від наявності локальних файлів і підтримки їх кодування у Chrome. Без вихідних медіафайлів це підтвердити неможливо.
