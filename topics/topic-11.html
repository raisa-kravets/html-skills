Знаходь, перевіряй і виправляй

Навчись знаходити помилки, перевіряти HTML і робити код зрозумілим та охайним.

Що ти навчишся робити

  • відкривати DevTools і знаходити HTML-елементи;
  • користуватися вкладкою Elements;
  • тимчасово редагувати HTML у браузері;
  • знаходити типові помилки;
  • перевіряти HTML через W3C Validator;
  • розуміти Error і Warning;
  • виправляти помилки поетапно;
  • оформлювати код відступами;
  • перевіряти власну HTML-сторінку перед завершенням роботи.

Що таке DevTools

DevTools — Developer Tools — це інструменти розробника, вбудовані у браузер.

  • переглядати HTML-структуру;
  • знаходити потрібний елемент;
  • бачити вкладеність;
  • тимчасово змінювати HTML;
  • аналізувати сторінку.

Як відкрити DevTools

F12
Ctrl + Shift + I
Права кнопка миші → Перевірити / Inspect

Зміни, зроблені у DevTools, не змінюють HTML-файл. Після оновлення сторінки вони зникнуть.

Панель Elements

Для цієї теми головною буде вкладка Elements. Елементи можна розгортати, бачити їх вкладеність, а при наведенні браузер підсвічує відповідну частину сторінки.

<body>
    <header>...</header>
    <main>...</main>
    <footer>...</footer>
</body>

Інструмент вибору елемента

Увімкни інструмент вибору, клацни на елемент сторінки й одразу знайди відповідний HTML-код.

На сторінці

Моє місто — Вінниця

У DevTools

<h1>Моє місто — Вінниця</h1>

Тимчасове редагування HTML

Було

<h1>Моє місто — Вінниця</h1>

Змінили у DevTools

<h1>Вінниця — моє місто</h1>

Текст у браузері зміниться, але HTML-файл — ні. Після F5 повернеться початковий текст.

Інтерактивна практика

1. Зміни, але не зламай

Чому зміна тексту <h1> у DevTools зникла після оновлення сторінки?

Чому браузер може показувати сторінку навіть із помилкою

<h2>Визначні місця Вінниці
<p>У місті є багато цікавих пам'яток.</p>

Пропущено </h2>. Браузер намагається показати сторінку, але структура коду вже неправильна.

Сторінка відкрилася — це ще не означає, що HTML-код правильний.

Типові HTML-помилки

Забутий закривальний тег

<p>Вінниця — місто на Поділлі.

Правильно:
<p>Вінниця — місто на Поділлі.</p>

Порядок закривання

<p><strong>Важлива інформація</p></strong>

Правильно:
<p><strong>Важлива інформація</strong></p>

Незакриті лапки

<img src="images/tower.jpg" alt="Вежа Артинова>

Правильно:
<img src="images/tower.jpg" alt="Вежа Артинова">

Посилання

<a href="about.html>Про місто</a>

Правильно:
<a href="about.html">Про місто</a>

Закривання section

<section>
  <h2>Історія</h2>
<section>

Правильно: </section>

Елемент, який відкрили останнім, закривається першим.

2. HTML-детектив

Натискай проблемні рядки й обирай правильне виправлення.

Обери правильний рядок:

Валідація HTML

Валідація HTML — це перевірка коду на відповідність правилам HTML. Браузер може показати сторінку навіть із помилками, а валідатор перевіряє сам код.

Де перевірити HTML-код?

Використовуй офіційний W3C Markup Validation Service.

Перевірити HTML-код у W3C Validator

Як працювати з W3C Validator

  1. Відкрий посилання на валідатор.
  2. Обери Validate by Direct Input.
  3. Встав HTML-код у поле.
  4. Натисни Check.
  5. Переглянь повідомлення.
  6. Почни з першої помилки.
  7. Виправ її у своєму HTML-файлі.
  8. Збережи файл: Ctrl + S.
  9. Знову встав оновлений код.
  10. Натисни Check повторно.

Error

Помилка, яку потрібно виправити.

Warning

Попередження: код працює, але є потенційна проблема.

Спочатку виправ першу помилку. Одна помилка може спричинити кілька наступних повідомлень.

Приклад

<section>
  <h2>Про місто<h2>
  <p>Вінниця — сучасне українське місто.</p>
</section>

Правильно: <h2>Про місто</h2>

Алгоритм пошуку помилки

  1. Не переписуй весь код.
  2. Знайди місце, де почалася проблема.
  3. Через DevTools знайди відповідний елемент.
  4. Перевір тег, вкладеність, лапки, href і src.
  5. Виправ одну помилку.
  6. Збережи Ctrl + S.
  7. Онови F5.
  8. Перевір результат.
  9. Перевір код у W3C Validator.
  10. За потреби повтори.

Оформлення HTML-коду

Погано для читання

<header><nav><a href="index.html">Головна</a><a href="about.html">Про місто</a></nav></header>

Зручно для читання

<header>
    <nav>
        <a href="index.html">Головна</a>
        <a href="about.html">Про місто</a>
    </nav>
</header>

Охайний код легше читати, перевіряти, виправляти й доповнювати.

Відступи та вкладеність

<main>
    <section>
        <h2>Про Вінницю</h2>
        <p>Вінниця розташована на берегах Південного Бугу.</p>
    </section>
</main>
main
└── section
    ├── h2
    └── p

3. Помилка чи неохайний код?

<h2>Про місто<h2>

<section><h2>Історія</h2><p>Текст</p></section>

<img src="tower.jpg" alt="Вежа Артинова>

<section>
<h2>Історія</h2>
<p>Текст</p>
</section>

Правила охайного HTML

  1. Вкладені елементи мають відступ.
  2. Елементи одного рівня мають однаковий відступ.
  3. Відкривальні та закривальні теги легко читати.
  4. Між великими блоками можна залишати порожній рядок.
  5. Значення атрибутів записуємо в лапках.
  6. Не залишаємо випадкових зайвих пробілів.
  7. Назви файлів і шляхи записуємо уважно.
  8. Перед завершенням перевіряємо HTML через W3C Validator.

Комплексне завдання

Врятуй HTML-сторінку

  1. Виправ <h2>, alt і вкладеність <strong>.
  2. Наведи порядок у відступах.
  3. Перевір сторінку через DevTools і W3C Validator.
    

    
    Самоперевірка
    • структура HTML правильна;
    • є <!DOCTYPE html>;
    • <html>, <head>, <body> записані правильно;
    • теги закриваються, вкладеність правильна;
    • лапки атрибутів закриті;
    • href і src перевірені;
    • <img> має alt;
    • код має відступи;
    • HTML перевірено через W3C Validator.
    

    
    🚀 Наскрізний проєкт «Моє місто — Вінниця»
    Перевіряємо готовий сайт
    У цій темі не створюй нові сторінки, розділи, тексти чи зображення. Не змінюй дизайн, меню та не додавай CSS.
    📁 Перевір усі файли
    • index.html
    • about.html
    • tower.html
    • pirogov-museum.html
    • europe-square.html
    
      
    1. Перевір структуру документа
    У кожному файлі знайди <!DOCTYPE html>, <html lang="uk">, <head> і <body>. Перевір, чи всі основні частини HTML-документа розміщені правильно.
    
      
    2. Перевір структурні елементи й заголовки
    Знайди <header>, <main> і <footer>. Усередині <main> перевір, чи правильно розміщені та закриті використані <section>.
    • на кожній сторінці має бути один <h1>;
    • основні розділи мають заголовки <h2>;
    • усі відкривальні та закривальні теги відповідають один одному.
    
      
    3. Перевір посилання та зображення
    Для кожного <a> перевір href. Для кожного <img> перевір:
    • src;
    • alt;
    • правильність шляху;
    • закриті лапки в атрибутах.
    Клацни створені посилання та переконайся, що вони відкривають потрібні сторінки. Не створюй нове меню і не додавай нових посилань.
    
      
    4. Перевір сторінки через DevTools
    1. Відкрий сторінку у браузері.
    2. Натисни F12.
    3. Відкрий вкладку Elements.
    4. Знайди <header>, <main>, один <section> та <footer>.
    5. Наведи курсор на елементи.
    6. Перевір, яку частину сторінки підсвічує браузер.
    
      
    5. Перевір відступи та вкладеність
    <main>
    <section>
        <h2>Заголовок розділу</h2>
        <p>Текст розділу.</p>
    </section>
</main>
    Особливо перевір <header>, <nav>, <main>, <section>, <article>, <div> і <footer>. Кожен відкритий парний тег повинен мати відповідний закривальний тег.
    
      
    6. Перевір усі файли через W3C Validator
    Перевірити HTML-код у W3C Validator
    1. Натисни «Перевірити HTML-код у W3C Validator».
    2. Відкриється режим Validate by Direct Input.
    3. Встав HTML-код у поле.
    4. Натисни Check.
    5. Знайди першу помилку.
    6. Виправ її у своєму HTML-файлі.
    7. Збережи файл.
    8. Встав оновлений код.
    9. Натисни Check ще раз.
    10. Повторюй, доки помилки HTML не будуть виправлені.
    
      
    Що має вийти
    Після виконання цього завдання зовнішній вигляд сайту майже не зміниться. Головний результат — правильно структуровані, перевірені й охайно оформлені HTML-файли.
    • 5 робочих HTML-сторінок;
    • правильна структура документів;
    • правильна вкладеність елементів;
    • справні посилання;
    • правильні шляхи до зображень;
    • заповнені alt;
    • охайні відступи;
    • HTML, перевірений через W3C Validator;
    • виправлені помилки валідації.
